# v0.1 scope and acceptance

Goal: self-host NiceOTP, use two independent CLI devices, synchronize encrypted
TOTP records and recover without giving the service operator a decryption key.

Delivered scope:

- Independent public Rust workspace and Apache-2.0 license.
- Dedicated PostgreSQL migrations; public OIDC authentication and user isolation.
- Client-only AEAD, password/recovery wrappers and optional OS keyring storage.
- Complete CLI record lifecycle, TOTP, encrypted local outbox and explicit conflicts.
- Idempotent, atomic multi-device synchronization and non-resurrectable tombstones.
- Whole-manifest authenticated backup and offline/new-account recovery.
- Docker deployment, local Dex example, macOS/Linux CI binaries and test documentation.

Validation is reproducible, not inferred from compilation:

1. `cargo test --workspace`: crypto binding/tampering/KDF bounds, all RFC6238
   Appendix B vectors, recovery independence, offline backup, public v1 vector,
   cached-key validation, and lost header-create/update responses over real sockets.
2. `scripts/e2e.py`: actual PostgreSQL 17 and HTTP, real RSA OIDC validation and
   browser PKCE callback, multiple users/clients, offline conflicts, trash/restore,
   permanent deletion, idempotency, concurrent writers, transaction rollback,
   uncertain request retry, batched import/restore, session revocation and
   plaintext canaries across database/logs/local files.
3. `scripts/dex_smoke.py`: the documented real Dex identity provider, login form,
   PKCE, token validation and local session creation.
4. CI: formatting, warnings-as-errors lint, Rust tests, PostgreSQL E2E, and native
   macOS/Linux CLI builds. The container workflow builds the deployment image.

No independent security audit has been performed. Unit/integration tests are not
an audit. Current implementation limits and threat boundaries are documented in
self-hosting.md and cryptography.md.

Deferred: WeChat, GUI clients, HOTP, sharing, trusted-contact/device pairing,
Passkey unlock, public hosted operations, legacy NiceOTP migration and full
compromised-key rotation. These require explicit follow-up design and validation.
